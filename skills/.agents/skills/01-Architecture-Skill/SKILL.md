# 1. Name

Hexagonal Architecture Skill

# 2. Description

This Skill defines the architectural standards that all generated backend projects must follow.

This Skill establishes:

Hexagonal Architecture (Ports and Adapters)

Layer separation

Dependency rules

Module organization

Package structure

Naming conventions

Module isolation

Repository architecture

Platform structure

File generation rules

This Skill does not define:

Business rules

Endpoints

GraphQL operations

REST operations

Database schemas

Security policies

Docker configuration

Build configuration

Infrastructure technologies

Project-specific settings

Those concerns belong to Specifications and specialized Skills.

# 3. General Rules

# 3.1 Specification Driven Configuration

The Architecture Skill MUST NEVER hardcode:

Company names

Package names

Root namespaces

Project names

Module root folders

The active Specification is the only source of truth.

Required Specification variables:

BasePackage

Example:

BasePackage = io.joyit

# 3.2 Objective

Ensure all generated projects follow a consistent, maintainable and scalable Hexagonal Architecture.

The architecture must:

Separate business logic from infrastructure.

Isolate external dependencies.

Support module independence.

Facilitate testing.

Support long-term maintainability.

# 3.3 Architectural Style

The project MUST follow:

Hexagonal Architecture (Ports and Adapters)

Core layers:

Domain

Application

Infrastructure

3.4 Dependency Direction

Allowed

Infrastructure → Application → Domain

Application → Domain

Forbidden

Domain → Application

Domain → Infrastructure

Application → Infrastructure

The Domain layer MUST remain completely independent.

# 3.6 Module Isolation Rules

Each business module MUST be self-contained.

Every module owns its own:

Domain

Application

Infrastructure

Persistence

GraphQL

REST

Forbidden

Direct repository access between modules

Cross-module communication MUST happen through:

Ports

Use Cases

Application Services

Events

# 3.7 Validation Rules

Java packages MUST match physical folder structure.

The generator MUST create folders before creating files.

Package declarations and folder paths MUST always match.

No generated class may violate the dependency direction rules.

# 5. Platform Directory

Location
<BackendContractDir>/src/main/java/<BasePackage>/platform
Ownership

This section is the single source of truth for:

Platform directory structure
Mandatory Platform submodules
Mandatory Platform files
Platform generation rules
Platform initialization rules
Purpose

Platform defines all shared technical infrastructure required at system bootstrap.

Platform MUST be fully generated BEFORE any business module exists.

⚠️ CRITICAL RULE

Platform is NOT optional and MUST NOT be partially generated.

If Platform exists → ALL mandatory files must exist.

Internal Structure

The generator MUST always create:

platform
├── configuration
├── exception
├── messaging
├── security
│   └── jwt
├── shared
└── storage
🚨 MANDATORY FILE CONTRACTS (NEW)

Each submodule MUST contain at least one bootstrap artifact.

5.1 configuration (MANDATORY FILES)
PlatformConfiguration.java

Purpose:
Bootstrap shared configuration behavior.

5.2 exception (MANDATORY FILES)
PlatformException.java
ErrorResponseMapper.java

Purpose:
Standardize error handling across system.

5.3 messaging (MANDATORY FILES)
RabbitMQConfiguration.java
MessagingChannels.java

Rules:

MUST define explicit channel names
MUST NOT use wildcard (*)
MUST define:
events-in
events-out
5.4 security/jwt (MANDATORY FILES)
JwtGenerator.java
JwtKeyGenerator.java
JwtConfig.java

Purpose:
JWT generation, signing, and key management.

5.5 shared (MANDATORY FILES)
Constants.java
5.6 storage (MANDATORY FILES)
MinioClientProvider.java
StorageConfiguration.java
Generation Rules
Platform MUST be generated FIRST
Platform MUST NOT be empty
Every submodule MUST contain at least one file
No submodule can be skipped
No wildcard messaging allowed
No partial generation allowed
Dependency Rules

Platform MAY depend on:

Framework libraries
External infrastructure clients

Platform MUST NOT depend on:

Any business module
Domain logic
Application services

Forbidden Content

Responsibilities
